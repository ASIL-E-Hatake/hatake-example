# 機能網羅（人が最初に書いたメモ）

> **これは人が書いた紙です。** ただし業務の案件ではありません ──
> この見本の「案件」は、**DSL で書けることを全部いちど書いて動かすこと**そのものです。

## 何のために作るか

1. **1.0 で凍らせる前に、全部いちど動かしておく**。
   一度も動かしたことのないキーを凍らせるのが、いちばん高くつく間違いなので。
2. **版を上げたときの影響を1か所で見る**。出力（読み返し・設計資料・値・画面）を
   固定してあるので、`hatake.version` を上げて回すと**差分がそのまま移行手順書**になる。

## 業務のふりはしない

- データは決め打ち（DB を持たない）。保存しても残らない
- 認証は持たない。役割は URL の `?role=tester,admin` で切り替える
- 納品物の見本ではない。人に見せる設計書としての値打ちは狙わない

**業務らしさが要る見本は別に2本ある**（マスタメンテ・受注入力）。こちらはそれとは
役割が違う。

## 画面は「確かめたいこと」で分ける

業務で分けると、落ちたときにどこが悪いのか分からない。

| 画面 | 確かめたいこと |
|---|---|
| 条件の組み合わせ | `all` / `any` / `not` と入れ子、既定値 |
| 押す前に聞く | 押す前に値を聞く・区切って実行・行ごとの有効条件・別タブ・成功後に移動 |
| 選択肢の連動 | 親で子を絞る・取る数の上限・ページ送りを切る |
| 畳み込み | 並べてから上位だけ畳む・切ったことを言う・詳細のボタン |
| ステップ入力 | ウィザードのボタン・条件で飛ばすステップ |
| 帳票（降順） | 降順で刷る・持ち出しは役割で絞る |

## 網羅できているかは、機械が数える

`spec/reference.json` の **(ノード, キー) 249組**を台帳にして、
`node tool/check-coverage.mjs` が「まだ一度も書かれていない所」を数える。

**書けないものは理由つきで除外表に書く。** 理由を書かせないと、
「たまたま漏れた」と「意図して外した」が区別できず、凍結の判断に使えない。
