# 01. 2本目からの進め方（道具を使い回す）

**目的**: 1本目で作った道具を、案件ごとに作り直さない。

## 何が使い回せるか

| 道具 | 何をするか | 案件ごとに書くもの |
|---|---|---|
| `tools/build-design-docs.mjs` | 設計資料7枚を定義から起こす | `tools/design.config.json` |
| `tools/refresh-docs.sh` | `出力-*.txt` を作り直す | なし |
| `tools/run-tests.sh` | 値・API・画面のテストを回して記録を作る | `tools/test.config.sh` |
| `tools/api-report.mjs` | API の実行記録を Markdown にする | ケースの並びだけ |

**1本目では案件の中に置いていました。** 2本目でそのまま動いたので上げています。

## 上げるときに必ずやること

道具を動かす場所を変えると、出てくる紙が変わることがあります。
**変わらないことを確かめてから**上げてください。

````
tools/ の下の道具を案件の外（リポジトリ直下の tools/）に上げて、
案件側には設定ファイルだけを置く形にして。

**上げたあとに1本目の生成物を作り直して、git diff がゼロになることを確かめて。**
1文字でも変わるなら、それは道具が変わったということなので報告して。
````

差分がゼロなら、その道具は案件をまたいで安全に使えます。

## 新しい案件を始めるとき

````
apps/<案件名>-prj/ を作って、1本目と同じ形で始めたい。
まず docs/1-要件定義/案件の説明.md に私が書く内容を待って。

フォルダの形は apps/master-maintenance-prj/ に合わせて、
tools/ には design.config.json と test.config.sh だけ置いて
（道具そのものはリポジトリ直下の tools/ を呼ぶ）。
````

## 効果（実測）

2本目で新しく書いた道具のコードは **0行**でした。設定ファイル2枚（合計 30 行）だけです。
