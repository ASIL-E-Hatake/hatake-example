# 04. 枠組み無し版と比べる（測るために2回作る）

**目的**: 「どれくらい楽になるか」を、見積もりではなく**測った数字**で言う。

## 先に線を引く（ここを外すと茶番になる）

````
同じシステムを hatake 無しでもう一度作って、比べたい。
比較が茶番にならないように、先に決めておきたいことがある:

1. **同じ業務**。画面5枚・役割3つ・入力の規則は1つも減らさない
2. **同じ DB**。スキーマも種データも同じファイルを共用する
3. **同じテスト**。API テスト28件を**1文字も変えずに**無し版にも通す
4. **普通の作り方**。「ミニ hatake を自作」ではなく、その言語で普通に選ぶ道具を使う
   （Java なら Bean Validation、Flutter なら素の Widget）

4 が特に大事。自作の枠組みと比べたら hatake が勝つのは当たり前で、測る意味がない。

置き場は apps/<案件>-prj/no-framework/ にして、README に
「これは納品物ではなく、比べるために作ったもの」と書いて。
````

## 測るもの

| | 測り方 |
|---|---|
| 行数 | コメントと空行を除く。**両方とも同じ基準**で数える |
| 同じものが作れたか | 同じテストを通す。通らなければ「作れていない」 |
| 両方で同じファイル | diff で数える＝**枠組みの有無で変わらない所** |

## 結果を書くときの決めごと

````
測った結果をまとめて。書くときの決めごと:

- **予想が外れたら、外れたと書く**。都合のいい数字だけ並べない
- 見積もりと実測を**混ぜない**（人日は測れないので見積もりと明記する）
- 作れなかったものがあれば、そう書く（数字合わせに口を足さない）
- この比較の限界（1人が続けて2回作った、など）を最後に書く
````
