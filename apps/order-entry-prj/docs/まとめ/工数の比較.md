# 工数の比較（2本目・**実測**）

> **1本目との違い: この紙の数字は見積もりではありません。**
> 同じ受注入力システムを**hatake 有りと無しの2回作って**、行数を数え、
> **同じ28件の API テストを両方に通して**測りました。
>
> 無し版の実物は [`no-framework/`](../../no-framework/) に置いてあります。

---

## 1. 測り方（先に読んでください）

比較が茶番にならないよう、先に線を引きました。

| | |
|---|---|
| **同じ業務** | 画面5枚・役割3つ・受注入力の規則は1つも減らさない |
| **同じ DB** | スキーマも種データも[同じファイル](../../docker/postgres/)を共用 |
| **同じテスト** | [API テスト28件](../../tests/api/run.mjs)を**1文字も変えずに**両方へ |
| **普通の作り方** | 無し版は「ミニ hatake を自作」ではなく、**Spring Boot ＋ Jakarta Bean Validation ＋ Flutter の Widget** ── AI に素直に頼んだら出てくる形 |

最後の1つが肝です。自作の枠組みと比べれば hatake が勝つのは当たり前で、
測る意味がありません。

## 2. 結果（行数・コメントと空行を除く）

| | hatake 版 | 無し版 | 倍率 |
|---|---|---|---|
| **画面（Dart）** | 399 | **2,164** | **5.4倍** |
| **API（Java）** | 1,148 | 1,163 | 1.01倍 |
| 定義（YAML） | 299 | 0 | — |
| **合計** | **1,846** | **3,327** | **1.8倍** |

### 予想と違ったこと: サーバ側はほぼ引き分け

**「AI が書く量が 1/4 になる」は、サーバ側については成り立ちませんでした。**
差は15行です。1本目のまとめは見積もりでそう書いていたので、ここで訂正します。

理由ははっきりしています。

- **両方でまったく同じファイルが8枚**あります（認証・監査・DB・出荷連携・
  マスタ照会）。もともと**枠組みの外**と宣言してある所なので、1行も減りません
- 残りも「DB にどう当てるか」が主で、そこは枠組みが持たない所です

hatake 版が減らしたのは**業務の規則を Java に書くこと**でした:

| 無し版で書いたもの | 行 |
|---|---|
| `OrderRequest`（注釈つき DTO） | 72 |
| `CrossFieldRules`（項目・行をまたぐ規則） | 108 |
| `OrderQuery`（検索の白名簿・型・並べ替え） | 147 |
| `ColumnRoles`（列の出し分け） | 59 |
| **計** | **386** |

その代わりに定義 YAML が **299行**。**置き場所が変わっただけ**です。

### 差が出たのは画面側

| 無し版のファイル | 行 | hatake 版では |
|---|---|---|
| `order_entry_page.dart` | 528 | `type: wizard` ＋ `steps` ＋ `computed` 3行 |
| `order_search_page.dart` | 445 | 条件6・列8・ボタン4を並べるだけ |
| `dashboard_page.dart` | 340 | カード7ブロック（集計もグラフも枠組み） |
| `order_slip_page.dart` | 320 | `report:` 6行（改ページも小計も枠組み） |
| `order_detail_page.dart` | 180 | 枠と項目を並べるだけ |
| `rules.dart` ＋ `totals.dart` | 195 | **0**（定義と枠組みが持つ） |

hatake 版の画面 399行には、**画面を組むコードが1行もありません**。中身は
Repository の対応表・計算 `op: tax` の登録・一括プラグイン・CSV と印刷の出し先・
ログイン画面だけです。

## 3. 行数より大きい差が3つあります

### ① 同じ規則を2か所に書く

無し版では、まったく同じ規則が Java と Dart の両方にあります。

| 規則 | Java | Dart |
|---|---|---|
| 必須・桁 | `OrderRequest` の注釈 | `rules.dart` の `header()` |
| 納期 ≧ 受注日 | `CrossFieldRules` | `rules.dart` |
| 同じ商品を2行に入れない | `CrossFieldRules` | `rules.dart` |
| 税率ごとに1回だけ切り捨て | `OrderTotals.java` | `totals.dart` |
| 列の出し分け | `ColumnRoles` | `order_search_page.dart` |
| 一括の上限 20 件と文言 | `BulkController` | `order_search_page.dart` |

**片方だけ直しても、誰も何も言いません。** 画面から消えたのに API では取れる
（またはその逆）になり、気づくのは使う人です。

hatake 版はこれが全部「定義に1回」で、画面もサーバも**同じその1枚**を読みます。

### ② 設計書が出ない

hatake 版の [2-設計](../2-設計/) は**全部生成物**です（画面一覧・遷移図・画面設計書5枚・
API一覧・権限マトリクス）。定義を直したら作り直すだけなので腐りませんし、
`--check` で CI が古さを見ます。

無し版には定義が無いので、**同じ紙を出す口がありません**。手で書くことになり、
書いた瞬間から腐りはじめます。この紙を作る工数は上の行数に入っていません。

### ③ 道具が検算してくれない

hatake 版で道具が止めてくれたもの（この案件だけで）:

- 紙に収まらない列幅（A4 横 841.89pt に対して 990pt 要る）
- 一度も効かない上限（`maxRows: 100` なのに1ページ 50 件）
- 呼ばないことにした言葉がラベルに入っている
- **人が決めないと決まらないこと**（同時更新・部分失敗・端数・帳票の値）を11件

無し版でこれらに当たるものは**ありません**。

行数は測れますが、人日は測れません（1人で両方作ったので、2本目は仕様が頭に入っている）。
**目安として**置きます。

| | 人だけ | AI だけ（枠組み無し） | hatake ＋ AI |
|---|---|---|---|
| 要件を書く | 2.0 | **1.0** | **1.0** |
| 業務の判断をする | 1.0 | **1.0** | **1.0** |
| 設計書を書く | 4.0 | 3.0 | **0.1**（生成） |

> 行数が引き分けだったので、工数も引き分けと見るのが素直です。

## 5. 同じものは作れましたか

**27 / 28 件が同じ結果になりました。** [無し版の実行記録](../../no-framework/出力-APIテスト結果.md)

落ちた1件は `A-28 画面の定義を配っている`（404）。**無し版には配る定義が存在しません**。
数字を揃えるために口を足す、はしていません。

途中で無し版だけ落ちた件がもう1つあり、直しました:

> **A-12** … `@Valid` を素直に付けると、注釈で1件でも引っかかった時点で例外になって
> 止まるので、項目をまたぐ規則（納期≧受注日）が一度も走りません。担当が空で納期も
> 逆のとき、押した人には「担当が空です」だけが返り、**直して送り直して初めて**
> 「納期が逆です」と言われる ── 往復が1回増えます。
>
> 画面を触っていても気づきません。**テストだけが見つけました。** 直すのに20行ほど
> 増えています。hatake 版は定義の規則を1回で全部回すので、そもそも起きません。

### 作れなかったもの

**PDF です。** 用紙の大きさ・1枚に載る行数・改ページ・日本語フォントの埋め込みを
自分で書くのは割に合わないと判断して、無し版は画面のプレビューと CSV までにしました。
hatake 版は `hatake_print` を入れて `reportPdf(...)` を1回呼ぶだけです。

**これは手抜きではなく測定結果**なので、そう書いてボタンにもそう出しています。

## 6. 自分の案件に置き換える式

```
減る工数 ≒ （画面の数 × 画面1枚ぶんの手間） × 0.8
         ＋ （設計書の枚数 × 1枚ぶんの手間） × 0.95
減らない  ＝ 要件を書く ＋ 業務の判断 ＋ 枠組みの外（認証・監査・外部連携・DB）
```

- **画面が多いほど効きます**（画面側が 5.4 倍だったので）
- **サーバだけの案件では効きません**（引き分けでした）
- **1〜2画面で終わる案件は、AI だけのほうが速いはずです**（DSL を覚える分と、
  枠組みの外を作る分が回収できない）

## 7. この比較の限界

- **1人が続けて2回作った**ので、2本目は仕様が頭に入っています（人日の見積もりが甘い方向）
- 行数はコメントと空行を除いていますが、**書き方の好みで2割は動きます**
- 無し版は PDF を作っていません（上記）
- 測ったのは**作るところまで**で、**直し続けるところ**は測っていません
  （定義1枚を直すのと、Java と Dart を両方直すのとでは差が開くはずですが、
  数字は持っていません）
