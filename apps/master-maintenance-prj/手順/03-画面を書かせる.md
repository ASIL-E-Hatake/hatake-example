# 03. 画面を書かせる（AI の仕事）

**目的**: 定義（`definitions/app.yaml`）を作る。人は1行も書かない。

## AI に投げる

````
definitions/hatake.project.yaml を読んでから、社員・部署・取引先の3マスタを
1枚の app 定義にして definitions/app.yaml に書いて。

要件は docs/1-要件定義/案件の説明.md のとおり。特に:
- 社員番号は6桁の数字。**採番しない**（前書きの決めごと）
- 退職者は消さない。在籍区分を変えるだけ
- 内線は admin と hr だけに見せる
- 取引先の検索は、範囲（与信限度額）と複数選択（締め日）を使いたい
- インボイス登録番号は法人のときだけ必須

書けたら hatake check --project にかけて、**警告ゼロ**になるまで直して。
**助言（好み）は当てる前に何を当てるか教えて**。案件の判断が要るものは私が決める。
````

→ `/画面` でも同じ。

## 必ず入れる3つ

| | なぜ |
|---|---|
| **前書きを先に読ませる** | 読ませないと用語が揺れる（「在籍区分」が「ステータス」になる） |
| **警告ゼロまで** | 警告は事実。直すのに業務の判断は要らないので、AI に任せていい |
| **助言は勝手に当てさせない** | 助言は好み。案件によって答えが違う |

## 出てくるもの

- `definitions/app.yaml`（この案件では約400行・画面4枚）
- [出力-読み返しと助言.txt](../docs/2-設計/出力-読み返しと助言.txt)

## 終わりの判定

````
npx hatake check definitions/app.yaml --project definitions/hatake.project.yaml
````

事実（警告）が **0件**。助言は0でなくてよい。

## 実際に起きたこと

**一括の上限を 100 件にしたら、道具に止められた。**

> 「まとめて退職にする」の上限は 100 件ですが、この表は1ページ 50 件です。
> 選べるのは**画面に出ている行**だけなので、100 件は選べません＝**この上限は一度も効きません**。

書けてしまうし、画面も普通に出る。**押してみても気づけない**種類の間違い。
→ 上限を 50 件（hr は 20 件）に直した。

**助言が1件出た。**

> 「まとめて退職にする」の失敗の言い方は件数だけです。**どの行が落ちたか**を言えないので、
> 押した人は全部やり直すか、当たりを付けて探すことになります。

これは業務として妥当だったので当てた（`{failedKeys}` を文言に足した）。
