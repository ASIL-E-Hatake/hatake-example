# 04. 問いに答える（人の本番）

**目的**: **定義に書けないのに、画面がある以上決まっていないと嘘になること**を決める。

検証（事実）も助言（好み）も**定義に書けること**しか見ない。ここだけが抜ける。

## AI に投げる

````
hatake ask definitions/app.yaml --project definitions/hatake.project.yaml
を回して、決めていないことを出して。

**答えは私が決めるので、勝手に決めて書かないで。**
````

→ `/検収` でも同じ（`check` と一緒に回る）。

## 出てくるもの

この案件では **6件** 返ってきた。どれも AI には答えられない（業務の判断）。

| 問い（id） | 何を聞かれたか | **人が決めたこと** |
|---|---|---|
| `concurrency` | 同時に直したらどちらが残るか | 更新日時が変わっていたら弾いて読み直させる |
| `partial-failure` | 一括が途中で失敗したら | 1件ずつ確定して、失敗した行だけ残す |
| `validation-server` | 画面の検証をサーバでも見るか | 見る（同じ定義で回す） |
| `role-source` | 役割はどこから来るか | ログイン時にこのシステムが返す（将来 AD） |
| `audit` | 監査を残すか | 削除と一括は必ず残す |
| `notify` | 一括のあと知らせるか | 知らせない |

## 答えを残す

````
hatake ask が返した6件、こう決めました。前書きの logic に足して。
（上の表を貼る）

印（id）は hatake ask --kinds で引ける正しいものを使って。勝手な id を書かないで。
````

前書きの `logic` に1行足して `answers: [<印>]` を付ける。**次から同じ問いは出ない。**

## 終わりの判定

````
npx hatake ask definitions/app.yaml --project definitions/hatake.project.yaml
→ 決めていないことは見つかりませんでした。
````

## 実際に起きたこと

**存在しない印を書いて落とされた。**

最初 `soft-delete` や `auth-owner` という、それっぽいけど**表に無い id** を書いた。

> `questions.decided[0]`: "soft-delete" という問いはありません（`npx hatake ask --kinds` で引けます）。

正しくは `erase`（消したものを残すか）。**勝手な id は通らない**＝
「答えたつもりで答えていない」が作れないようになっている。

**区分を間違えても落とされた。**

> `logic[2].answers`: "numbering" は「サーバの担当」ですが、where に outside と
> 書いてあります（担当が違うなら、答えになっていないか区分が間違っています）。

## ここを抜かすと

「それっぽいけど誰も決めていない設計」が残る。**半年後に必ず揉める**のがこの6件。
