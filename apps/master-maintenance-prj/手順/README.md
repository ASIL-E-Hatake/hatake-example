# 実手順（人が AI に何をしたか）

この案件を作るときに**実際にやったこと**を、順番に置いてある。
コピペできる依頼文つき。別の案件でもそのまま使える。

> `docs/` が**成果物**（できあがった紙）で、こっちが**操作**（人がやったこと）。

## 人の仕事は3か所だけ

```
[人] 案件の説明を書く                  ← 01
  ↓
[AI] 枠組みの外を仕分ける              ← 01
  ↓
[人] 前書きを育てる                    ← 02
  ↓
[AI] 定義を書く → 自分で読み返す        ← 03
  ↓
[人] 返ってきた問いに答える             ← 04  ★ここが本番
  ↓
[AI] 設計資料を起こす（画面一覧・遷移図・設計書・API） ← 05
  ↓
[人] 何を確かめるかを決める → [AI] 回して記録を作る ← 06
```

| | 手順 | 誰が | だいたいの時間 |
|---|---|---|---|
| 01 | [仕分ける](01-仕分ける.md) | 人が書く → AI が仕分ける | 30分（書くのが大半） |
| 02 | [前書きを育てる](02-前書きを育てる.md) | AI が下書き → **人が直す** | 1時間 |
| 03 | [画面を書かせる](03-画面を書かせる.md) | AI | 30分（人は読むだけ） |
| 04 | [問いに答える](04-問いに答える.md) | **人** | 30分（相談が要ることも） |
| 05 | [設計資料を作る](05-設計資料を作る.md) | AI（人は読む） | 30分 |
| 06 | [テストしてエビデンスを残す](06-テストしてエビデンスを残す.md) | 人が決めて AI が作る | 半日 |

**定義 345 行は1行も手で書いていない。** 人が書いたのは案件の説明と前書きの2枚だけ。

## 始める前に

この案件のフォルダで Claude Code を開くと、[CLAUDE.md](../CLAUDE.md) が自動で読まれる。
そこに**案件の前書きから生成した節**が入っているので、毎回の依頼で用語や決めごとを
説明しなくていい。

CLAUDE.md と `.claude/` の作り方は
[Claude Code の設定](../../../docs/claude-code-setup.ja.md)。

## よく使う依頼（スラッシュコマンド）

毎回同じ文を打たなくて済むように `.claude/commands/` に入れてある。

| 打つもの | 何をするか |
|---|---|
| `/仕分け` | 資料を `hatake where --from` にかけて、枠組みの外を出す |
| `/前書き` | 前書きの下書きを起こす（**言っていないことは書かせない**） |
| `/画面` | 前書きを読ませてから定義を書かせ、`check` が通るまで直させる |
| `/検収` | `check` と `ask` を回して、残っているものを出す |
