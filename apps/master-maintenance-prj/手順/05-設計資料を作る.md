# 05. 設計資料を作る

**目的**: 定義を、**人が読む設計書**の形にする（画面一覧・画面遷移図・画面設計書・
API 一覧・権限マトリクス）。

## 先に知っておくこと

**枠組みは「1枚を説明する」までしか持たない。**

| 枠組みが持つもの | 持たないもの |
|---|---|
| `hatake explain --page <id> --markdown` … その画面が何をするか | **画面一覧**（並べる紙） |
| `hatake diagram --format mermaid` … 画面遷移図 | **API 一覧**（並べる紙） |
| `hatake explain --roles --matrix` … 権限マトリクス | **納品の体裁**（表紙・章立て） |
| `hatake design` … 意図と突き合わせた1枚 | |

**納品の様式は案件ごとに違う**ので、並べるところは `tools/` に自分で作る
（認証・エビデンスと同じ線の引き方）。この案件では
[tools/build-design-docs.mjs](../tools/build-design-docs.mjs)。

> **最初にこれを頼み忘れました。** テストは「ケース一覧を作って」と言ったので出てきたのに、
> 設計は「定義を書いて」としか言わなかったので、**人が読む設計書が無いまま**実装まで
> 進みました。要件のメモと定義はあるのに、**その間をつなぐ紙が無い**状態です。
> 頼めば出るので、**03 の直後に必ず頼んでください**。

---

## 人がやること

**どの紙が要るかを決める。** 客先に出す様式（章立て・粒度）は案件ごとに違うので、
そこだけは人が決めます。決まっていなければ下の5つで足ります。

## AI に投げる

````
定義から**人が読む設計書**を起こして。tools/build-design-docs.mjs にまとめて、
何度でも作り直せるようにして。

作るもの（docs/2-設計/ の下）:
1. 画面一覧.md      … 画面 ID・画面名・種別・データの出どころ・何をする画面か
2. 画面遷移図.md    … hatake diagram --format mermaid（GitHub でそのまま図になる）
                      ＋ 同じ図の SVG
3. 権限マトリクス.md … hatake explain --roles --matrix（誰に何が見えるか）
4. API一覧.md       … 画面が要求している API（Repository ごと）。
                      定義に書けない口（認証・一括）は「枠組みの外」として別表に
5. 画面設計書/<画面 id>.md … hatake explain --page <id> --markdown を1画面1枚に

決めごと:
- **全部、定義から起こす。手で書かない**（手で書いた設計書は、定義を直した日から嘘になる）
- どの紙にも「これは生成物です・作り直し方はこれ」と頭に書く
- `--check` を付けたら**古くなっていないか見るだけ**にして（CI に置く）
- YAML を自前の正規表現で読まない。**解析器はもう在る**ので `hatake explain --json` に聞く
````

**必ず入れる3つ:**

| | なぜ |
|---|---|
| **定義から起こす** | 手で書くと、定義を直したその日から古くなる。しかも**古い設計書は嘘をつく** |
| **「生成物です」と頭に書く** | 書いてないと、誰かが手で直してしまう（そして次の生成で消える） |
| **`--check` を付ける** | 作り直し忘れを CI が言う。言わないと必ず腐る |

> **YAML を自分で読ませない。** 1回目は行を正規表現で拾う書き方になって、空の画面を
> 拾って落ちました。`hatake explain --json` に聞けば、**枠組みの解析器**が答えます。

## 出てくるもの

| 紙 | 元 |

## 回す

```bash
node tools/build-design-docs.mjs          # 作り直す
node tools/build-design-docs.mjs --check  # 古くなっていないか（CI 用）
```

## 終わりの判定

- 5つの紙がそろっている
- `--check` が通る（定義と食い違っていない）
- **人が読んで意味が分かる**（ここだけは人。DSL のキー名が出ていたら、それは設計書ではない）

## 実際に起きたこと

| | |
|---|---|
| **`hatake openapi` が app 定義を読めない** | 単票の定義しか受け取らない（`--page` も無い）。API 一覧は **Repository の契約**から組んだ（画面ごとではなく Repository ごとに決まるので、むしろこちらが正しい粒度だった） |
| **`explain --roles --matrix --markdown` は Markdown にならない** | 幅を揃えた文字の表が出るだけなので、コード囲みに入れて貼った |
| **自前で YAML を読もうとして落ちた** | 行を正規表現で拾う書き方をして、空の画面を拾った。`explain --json` に聞く形へ直した |
