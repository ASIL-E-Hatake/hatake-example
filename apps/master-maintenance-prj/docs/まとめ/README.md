## 途中で起きたこと

**13件踏みました。** 見栄えのために減らしていません。

| 出どころ | 件数 | 深さ |
|---|---|---|
| フレームワーク本体の不具合 | 3 | 半日／件。どれも**外から使わないと出ない**種類 |
| 書き間違い（**道具が止めた**） | 4 | 数分。理由も一緒に出るので調べる時間が要らない |
| 書き間違い（**道具が止めなかった**） | 2 | 半日。テストを書くまで出ない |
| 環境まわり | 4 | 数十分 |

いちばん怖かったのは3つ目です。`{ type: pattern, value: ... }` と書いて（正しくは
`pattern:`）、**検証が一度も効かないのに警告ゼロで通りました**。テストを書いて初めて
出たので、**テストを省くと危ない**が具体的に分かりました。

→ 全部の内訳: **[起きた問題と対応](起きた問題と対応.md)**

## 課題（直っていないもの・向いていないもの）

**枠組みが持たないもの**を自分で書くことになります（この案件では約1,200行）:
認証・本当の権限遮断・監査・同時更新・一括の中身・納品資料の道具。
ただし**案件をまたいで使い回せる**ものが大半なので、**効果が出るのは2本目から**です。

**向いていない案件**もあります: 画面そのものが要件・1〜2画面で終わる・納品物が要らない。
