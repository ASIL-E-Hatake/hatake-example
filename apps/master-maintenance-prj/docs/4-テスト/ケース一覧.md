# テストケース一覧

この案件で確かめることの全部。**項番（S / A / G）は実行記録の項番と同じ字**なので、
この紙から結果へ辿れる。

| 種類 | 何を確かめるか | 件数 | 結果 |
|---|---|---|---|
| **S**（値） | 定義に書いた規則が**その値でどう効くか**。画面もサーバも要らない | 31 | [出力-シナリオ結果.txt](出力-シナリオ結果.txt) |
| **A**（API） | サーバが**同じ定義で**検証・遮断・上限を守っているか | 20 | [出力-APIテスト結果.md](出力-APIテスト結果.md) |

作り直し:

```bash
docker compose up -d

```

> **回すたびにデータを初期状態に戻している。** エビデンスは「何度回しても同じ」で
> なければ使えない（一括の試験が前回の続きから始まると、2回目から結果が変わる）。

## A — API のテスト

**画面の検証は親切であって守りではない**（API を直接叩けば通る）。だから同じことを
サーバでも確かめる。実行記録は投げたものと返ってきたものを**そのまま**載せている。

| 項番 | 確かめること | 期待 |
|---|---|---|
| A-01 | ログインできる（hr） | 200・roles に hr |
| A-02 | パスワードが違う | 401・**理由を分けない** |
| A-03 | ログインせずに一覧 | 401 |
| A-04 | 一覧が返る形 | `{items, totalCount}`（`hatake_http` の契約） |
| A-05 | 定義に無い条件 | **無視される**（許可リスト方式） |
| A-06 | 部分一致（氏名） | 絞られる |
| A-07 | 範囲＋複数選択（取引先） | 絞られる |

| A-09 | viewer の一覧 | **内線を返さない** |
| A-10 | hr の一覧 | 内線を返す |
| A-11 | 必須と項目間の違反 | 400・2件まとめて |
| A-12 | 社員番号の形が違う | 400 |
| A-13 | hr が取引先を登録 | **403** |

| A-20 | API の形を出す | 200・OpenAPI |

## 確かめていないもの（そう書いておく）

紙に書いていないことは、やっていないのと同じ。**都合の悪いことも残す。**

| | なぜ |
|---|---|
| 画面から実際に**保存する**操作 | スクショは開いた所まで。保存の合否は A-11 / A-12 が持つ |
| CSV の中身 | 出す口（ダイアログ）は見ているが、列と並びは確かめていない |
| 一括を**画面から**押したときの文言 | `{failedKeys}` が埋まるかは目で見ていない（API では A-16 で確認済み） |
| 印刷・帳票 | この案件には無い |
| 性能・同時接続 | この案件の範囲外（10人で使う想定） |
| ブラウザの種類 | Chrome だけ（スクショを撮った環境） |
