# 社内マスタメンテナンス

人事部と購買部が使う、社員・部署・取引先の管理画面。いまは Excel で管理していて、
更新のたびに情シスに依頼が来ている ── を想定した案件。

## 動かす

```bash
docker compose up
```

| | |
|---|---|
| **画面** | <http://localhost:8080> |
| API | <http://localhost:3000/api/health> |
| DB | localhost:5432（`hatake` / `hatake`） |

ログインは `admin / admin`、`hr / hr`、`viewer / viewer`。
**役割で見え方が変わる**ので、3つとも試すのがいちばん早い。

| | admin | hr | viewer |
|---|---|---|---|
| CSV 出力（社員・部署） | 出る | 出る | **出ない** |
| CSV 出力（取引先） | 出る | **出ない** | 出ない |
| まとめて退職にする | 出る（50件） | 出る（20件） | **出ない**（選択欄ごと消える） |
| 内線の列 | 見える | 見える | **見えない** |

> **Flutter SDK も Node も入れなくていい。** 1回目は Flutter Web のビルドで数分
> かかります（2回目からは速い）。`@hatake-fw/api` と Flutter のパッケージは
> [v0.9.14 の tag](https://github.com/ASIL-E-Hatake/hatake/releases/tag/v0.9.14)
> から入ります＝**レジストリに出していないものを git だけで配っている**形。

## 何が入っているか

| 画面 | 種別 | 見どころ |
|---|---|---|
| 社員マスタ | `crud` | 権限で列を隠す（内線）・一括で退職にする・CSV 出力 |
| 社員詳細 | `detail` | 一覧の行から遷移（`$row.employeeNo`） |
| 部署マスタ | `master` | 自分自身を選択肢に使う（上位部署） |
| 取引先マスタ | `crud` | **複雑な検索**（範囲・複数選択）・条件付き必須（法人だけインボイス番号） |

### 役割

| | admin | hr | viewer |
|---|---|---|---|
| 内線を見る | ○ | ○ | × |
| CSV 出力（社員・部署） | ○ | ○ | × |
| CSV 出力（取引先） | ○ | × | × |
| まとめて退職にする | ○（50件まで） | ○（20件まで） | × |

この表は定義から引ける:

```bash
npx hatake explain definitions/app.yaml --roles
```

> **画面の `roles` が止めるのは見せるかどうかだけ。** API を直接叩けばデータは取れるので、
> 本当の遮断は `node-src` 側でやっている（前書きの `authz-server` で決めたこと）。

## 定義

```
definitions/
├─ hatake.project.yaml    案件の前書き（**人が書く**。AI に最初に読ませる1枚）
├─ app.yaml               画面4枚（flutter-src と node-src が同じものを読む）
└─ hatake-registry.json   実装から作った「登録済みのもの」（手で書かない）
```

| | |
|---|---|
| [flutter-src/](flutter-src/) | 画面。**画面のコードは1行も無い**（配線とログインだけ） |
| [node-src/](node-src/) | API。同じ定義で検証・クエリ・DTO |

自分で確かめる:

```bash
npx hatake check definitions/app.yaml --project definitions/hatake.project.yaml
```

いまの状態: **警告0・助言0・未決の問い0**。

## 枠組みの外に置いたもの

hatake は業務ロジックも認証も持たない。この案件で外に置いたのはこれ:

| | どこ | なぜ |
|---|---|---|
| ログイン・資格の確認 | `node-src` | hatake は認証を持たない |
| 役割の遮断（本当の認可） | `node-src` | 画面の `roles` は見せ方だけ |
| 監査（誰がいつ何を） | `node-src` | 画面は押した結果しか知らない |
| 社員番号の採番 | しない（人が決める） | 既存の Excel と揃えるため |
| 一括退職の中身 | `flutter-src` のプラグイン | 何件ずつ・失敗したらどうするかはアプリ側 |

全部 `definitions/hatake.project.yaml` の `logic` に書いてある。
**書いてあるから AI が画面側に実装しない。**
