## 初見試験

同じ課題・同じモデル（claude-sonnet-5-5）・同じ Claude Code（2.1.292）で、hatake の版だけを
変えて6回ずつ回した。成績表は [v0.9.30](../evals/results/v0.9.30/成績表.md)（前の版との比較つき）。

| | v0.9.29 | v0.9.30 |
|---|---|---|
| 合格 | 6 / 6 | 6 / 6 |
| 断られた引数（のべ） | 2 | 2 |
| うち近い名前が添えられた | 0 | **2**（`query` → `name`・`key` → `name`） |
| `reference` が空振り（のべ） | 1（`maxLength`） | 2（`immutable`・`editable`） |
| 名前だけの npx ・答えが大きすぎた試行・`where` の「載っていない」・`examples` の空振り | 0 ・ 0 ・ 0 ・ 0 | 0 ・ 0 ・ 0 ・ 0 |

近い名前は効いた（断られた2回とも、添えられた名前で呼び直せた）。`maxLength` のような値の
空振りは無くなった。

**新しく見えたこと（枠組みに返す）**:

- **`reference` を「意味」で引いている**。「作ったあとは変えられない」を書こうとして
  `immutable` / `editable` を引き、どちらも「DSL に無い名前」だった（正しいのは `readOnlyWhen`）。
  キーの名前でも値でもないので、値で引けるようにしても当たらない。**意味の近いキーを添える
  表**（`readonly` / `immutable` / `editable` → `readOnlyWhen`、`disabled` → `enabledWhen`、
  `hidden` → `visibleWhen` …）が要る
- **必須の引数を渡し忘れたときの答えに例が無い**。`hatake_new_page` を `kind` / `id` 無しで
  呼んで「kind は必須です」とだけ返った（知らない引数を断るときは「呼び方の例」が付く）
