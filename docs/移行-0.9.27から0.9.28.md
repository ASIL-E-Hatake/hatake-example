# 見本を 0.9.27 → 0.9.28 に上げた記録

> **中身**: 実際に上げてみて、何が起きて何が起きなかったか。
> **前の回**: [0.9.26 → 0.9.27](移行-0.9.26から0.9.27.md)。
> 枠組み側で何が変わったかは [CHANGELOG](https://github.com/ASIL-E-Hatake/hatake/blob/main/CHANGELOG.md)
> の 0.9.28。

0.9.28 は、[初見試験](../evals/)（hatake を知らない AI に作らせて、動かして採点する）の
0.9.27 の回で見つかった**道具が黙っていた所**を3つ直した版です。

- MCP の道具は**知らない引数を断る**（黙って捨てていたので、`hatake_reference` に `key` と
  渡すと全体 10 万字が返っていた）。`hatake_reference` は名前を省くと目次
- 定義を受け取る MCP の道具は **`file`**（ファイルの道）でも受け取る（本文しか受け取らないので、
  AI は CLI の `check` に流れて名前だけの npx を打っていた）
- `where` の担当の表に**知らせ**（メール・通知＝サーバ）と**定期処理**（月末・バッチ＝業務ロジック）

## 初見試験：直したところが効いたか

同じ課題・同じモデル（claude-sonnet-5-5）・同じ Claude Code（2.1.292）で、hatake の版だけを
変えて6回ずつ回した。成績表は [v0.9.27](../evals/results/v0.9.27/成績表.md) ／
[v0.9.28](../evals/results/v0.9.28/成績表.md)。

| | v0.9.27 | v0.9.28 |
|---|---|---|
| 合格 | 6 / 6 | 6 / 6 |
| 答えが大きすぎた試行（全体 10 万字が返った） | 4 | **0** |
| 名前だけの npx（のべ） | 11 | **0** |
| `check` を CLI で ／ MCP で（のべ） | 10 ／ 1 | **0 ／ 8** |
| `file` で渡した（のべ） | — | 9 |
| `where` が「載っていない」と言った（のべ） | 6 | **0** |
| `examples` が空振り（のべ） | 5 | 2 |
| パッケージの中を読みに行った試行 | 1 | **0** |

合否は前から全部通っていたので、変わったのは**通り方**。ファイルに書いた定義を `file` で
MCP に渡すようになり、CLI に流れなくなったので、名前だけの npx も消えた。

**新しく見えたこと（枠組みに返す）**:

- **AI が Claude Code の `Write` に `file` を渡して断られた**（3試行・1回ずつ）。`Write` の引数は
  `file_path`。hatake の道具で `file` を覚えたぶん、引数名が混ざったように見える（1往復損する
  だけで済んでいる）。名前を `file_path` に揃えるかは枠組み側で決める
- **`where` の「メール」が項目名にも当たる**。マスタメンテの「社員番号・氏名・…・メール・内線」
  （項目の並び）が、0.9.28 で足した「知らせる（サーバの担当）」に当たった。外ではないので害は
  小さいが、言葉の当て方は直したい
- `examples` の空振りはまだ残る（「app 複数画面 メニュー」「マスタ 顧客 区分 検索」）。枠組みの
  ロードマップの候補「例を普段の言葉で引けるように」

## 生成物

「枠組みの外の仕分け」（`where --from`）の紙が2枚変わった。業務ロジックの説明に「決まった
時刻に動く処理も同じ」が足され、マスタメンテでは上の「メール」の行が1件増えた（当てられ
なかった行が 28 → 27）。設計資料・`CLAUDE.md` の印の中・出力紙のほかは変わっていない。

## 試験の道具

受注入力の API の試験が、1本目のログインで `ECONNRESET` で落ちた。データを初期状態に戻した
あと API を再起動して、**決め打ちで 5 秒**待っていた。Java の API がそれまでに立ち上がらない
日に落ちる（0.9.27 まではたまたま間に合っていた）。**口が応えるまで待つ**（最大 60 秒）に直した。

もう1つ、マスタメンテの「仕分け」の紙の末尾に `npm notice New major version of npm available!`
が混ざった。`refresh-docs.sh` は道具の出力を**標準エラーごと**紙に写していて、npm が日に1回
くらい出すお知らせまで入っていた（出たり出なかったりするので、同じ定義でも紙が変わり、
`--check` が古いと言う）。`refresh-docs.sh` と `run-tests.sh` で `NPM_CONFIG_UPDATE_NOTIFIER=false`
を立てて止めた。
