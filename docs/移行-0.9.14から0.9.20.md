# 見本3本を 0.9.14 → 0.9.20 に上げた記録

> **中身**: 実際に上げてみて、何が起きて何が起きなかったか。
> **前の回**: [0.9.12 → 0.9.14](移行-0.9.12から0.9.14.md)。
> 枠組み側で何が変わったかは [CHANGELOG](https://github.com/ASIL-E-Hatake/hatake/blob/main/CHANGELOG.md)
> の 0.9.15〜0.9.20。

この間に、ブラウザ版（Vue / React）の Renderer が入って、見た目が Flutter 版に
そろいました（0.9.16〜0.9.20）。**Flutter / Java / Node の案件から見ると破壊的な
変更はありません。**

## 結論から

| | 上げるために直した所 | ついでに直した所 |
|---|---|---|
| 定義（YAML） | **0 か所** | 1 か所（機能網羅の回り道を外した） |
| Flutter（Dart） | **0 か所** ── 3本とも `analyze` clean | 0 か所 |
| Java | **0 か所** | 1 か所（並べ替えの名前を渡す） |
| Node | **0 か所** | 2 か所（同じく） |
| 参照の差し替え | 10 ファイル（`v0.9.14` → `v0.9.20`） | |
| 組み方 | `.dockerignore` を3本に置いた（下の「つまずいた所 ①」） | |

**上げるだけなら1行も直していません。** 値の試験（`hatake run`）の結果も
3本とも 0.9.14 と同じでした。

## 見え方が変わった所

| 案件 | 何が変わったか |
|---|---|
| 機能網羅（Flutter） | 詳細画面の計算した項目（「合計」「上位3件」）が**埋まるようになった**。0.9.19 までは空のまま出ていた（C-05） |
| 機能網羅（Vue / React） | 見た目が Flutter 版にそろった（段組み・¥ 付きの数字・棒グラフ・表のカード・タブ・アイコン） |
| 3本とも | **「押せるのに並ばない」列が並ぶようになった**（下） |

### 「押せるのに並ばない」列が9つあった

0.9.18 まで `buildQuery` は**絞り込みに書いた項目でしか並べ替えを許さなかった**
ので、表の列に `sortable: true` と書いても、絞り込みに無い列は押しても並びません
でした。**画面は出る・エラーも出ない**ので、API を直接叩くまで分かりません。

数えたら3本で **7画面・9列**ありました:

| 案件 | 画面 | 並ばなかった列 |
|---|---|---|
| マスタメンテ | 社員マスタ | 入社日 |
| マスタメンテ | 部署マスタ | 部署コード |
| マスタメンテ | 取引先マスタ | 取引先コード |
| 受注入力 | 受注照会 | 取引先（顧客名） |
| 機能網羅 | 押す前に聞く | 名前 / 金額 |
| 機能網羅 | 選択肢の連動 | コード / 名前 |
| 機能網羅 | 見せる相手で変わる | コード |

0.9.19 から `buildQuery` が**並べ替えてよい名前**を受けるので、サーバで表を渡し
ました（どれも定義に書いてある名前で、利用者が送ってきた字は今までどおり通りません）:

```js
// Node（マスタメンテ・機能網羅）
buildQuery(page.search, query, { table: page.table })
```

```java
// Java（受注入力）
QueryBuilder.build(page.search(), params, 50, page.table())
```

機能網羅は、ダッシュボードの表のカードを「原価の高い順」に並べるためだけに、
要りもしない「原価（以上）」の絞り込みを定義に足していました。これも外しました
（カードの `sort.field` を並べ替えてよい名前として渡す）。

## 上げ方（やったこと）

1. `hatake.version` を `v0.9.20` に
2. `apps/*/flutter-src/pubspec.yaml` の `ref:` を3本とも差し替え
3. `apps/*/node-src/package.json` の `.tgz` の URL を差し替え（2本）
4. `apps/kitchen-sink-prj/{vue,react}-src/package.json` の `.tgz` の URL を差し替え
5. `apps/order-entry-prj/java-src/build.gradle` の JitPack の座標を差し替え
6. **イメージを焼き直してから**回す（下の ①）

前回と同じく、**版の数字は固定している所と履歴の記述とで分けること**。「0.9.12 で
直り…」のような記述は起きたことの記録なので、上げてはいけません。

## つまずいた所

### ① 上げたのに、古い版のまま動いていた

機能網羅の API サーバを `v0.9.20` に上げて焼き直したのに、中を見ると
**`0.9.14` のまま**でした。

Dockerfile は「`package.json` だけ先に入れて `npm install` → 残りを `COPY`」の形
です。手元に `node_modules` が在ると、**後の `COPY` が、入れ直したばかりのものを
手元の古いもので上書きします**。Flutter の `pubspec.lock` / `.dart_tool` も同じ罠
です。**画面は普通に出るので、版を確かめないと気づけません。**

3本とも `.dockerignore` を置いて、手元の生成物を持ち込まないようにしました。
上げたら中の版を確かめるのが確実です:

```bash
docker compose exec api node -p "require('@hatake-fw/api/package.json').version"
```

### ② JitPack が v0.9.20 を組めなかった

受注入力の Java は JitPack から入れています。JitPack は**初めて頼まれた版をその場で
組む**のですが、その組み立てが失敗していました:

```
Could not GET 'https://repo.maven.apache.org/.../snakeyaml-2.2.pom'.
Received status code 429 from server: Too Many Requests
```

こちらのコードではなく、JitPack が Maven Central から部品を取るときの混雑です。
**JitPack は失敗も覚えている**ので、待っていても直りません。組み直しは:

1. jitpack.io に GitHub でログインする（リポジトリに権限のあるアカウントで）
2. `ASIL-E-Hatake/hatake` を Look up して、Builds タブで失敗した版を消す
3. もう一度頼む（Get it を押すか、Gradle で引く）

組み直したら通りました。Builds タブには `v` の無い `0.9.20` という行も出ますが、
組み立ての記録を見ると **tag `v0.9.20` と同じ commit を組んだもの**で、出てきた jar も
同じでした。どちらの名前で頼んでも同じものが返るので、困ることはありません。

組み直しを待つ間は、手元の枠組み（tag と同じ中身）を Gradle の差し替えで当てて、
コンパイル・試験・jar まで確かめていました。組み直したあと JitPack から焼き直して、
同じ結果になることも確かめています。

### ③ 前の記録は、試験で作った行が残った状態で撮れていた

マスタメンテと受注入力の画面の証跡が、前回と違って見えました。比べると、**前回の
絵のほうに API の試験で作った行が混ざっていた**（社員番号 100025〜、受注
SO2026090101 など）。今回は初期データのまま撮れています。

### ④ 記録の揺れ（中身は同じ）

回すたびに変わるものがあります。中身が同じものは元に戻しました:

- JSON のキーの並び（Java の `Map.of` は起動のたびに並びを変える）
- ログインの token・更新日時
- API を叩いた URL の書き方（`api:3000` と `localhost:3003`）
- 画像の書き出しの1バイトの差

キーの並びは、並びをそろえて 28 個の JSON を突き合わせて、中身が全部同じことを
確かめてから戻しています。

### ⑤ 設計資料が、定義に追いついていなかった

「版を上げたら出力を全部作り直して差分を見る」をやったら、今回の上げとは関係の
無い古い差が2つ出ました。

- **機能網羅**: 画面を2枚足した（`role_crud` / `card_board`）ときに設計資料を
  作り直していなかった。画面一覧・権限マトリクス・画面設計書が6画面のままだった。
  今回8画面に追いついた
- **受注入力**: 設計書の「受注状態 … 選べるのは 入力中 / 確定 / 出荷済 / 取消」
  から**選択肢が消えた**。0.9.12・0.9.14・0.9.20 の `hatake explain` を並べると
  3つとも同じ出力で、**選択肢を語彙（`optionsOf`）に書き換えたときから**
  `explain` が選択肢を書かなくなっていた。設計書はそれより前の版で作ったまま
  だったので見えていなかった。枠組み側の不具合として別に直す

設計資料は「道具で作り直すもの・手で直さないもの」なので、今の道具が出したとおりに
してあります（枠組みが直ったら作り直せば選択肢は戻る）。
