# 見本3本を 0.9.20 → 0.9.23 に上げた記録

> **中身**: 実際に上げてみて、何が起きて何が起きなかったか。
> **前の回**: [0.9.14 → 0.9.20](移行-0.9.14から0.9.20.md)。
> 枠組み側で何が変わったかは [CHANGELOG](https://github.com/ASIL-E-Hatake/hatake/blob/main/CHANGELOG.md)
> の 0.9.21〜0.9.23。

今回は前回までと毛色が違って、**上げるだけでは終わらせていません。** 0.9.21〜0.9.23 は
「見本を作ってみて足りなかったもの」を枠組みに入れた版なので、見本の側で
**手で書いていた回り道を外して、定義に寄せる**ところまでやりました。

## 結論から

| | 上げるために直した所 | 新しい書き方に寄せた所 |
|---|---|---|
| 定義（YAML） | **0 か所** | 3本とも（下の「使ったもの」） |
| Flutter（Dart） | **0 か所** ── 3本とも `analyze` clean | 機能網羅の `saveItem` を外した |
| Vue / React | **0 か所** | 同じく `saveItem` を外した |
| Java | **0 か所** | 役割の決め打ちと手書きの SQL を外した |
| Node | **0 か所** | 役割の決め打ちと、受け取る項目・返さない列の手書きを外した |
| 参照の差し替え | 10 ファイル（`v0.9.20` → `v0.9.23`） | |

**上げるだけなら1行も直していません**（破壊的な変更は無し）。上げると新しく出る
助言はあります（0.9.22 で入った `crud-without-create`＝「入力欄があるのに新規登録が
無い」。機能網羅の2画面で出たので、新規登録を足した）。

## 外した回り道

### マスタメンテ（Node）

| 0.9.20 まで | いま |
|---|---|
| `server.js` に `write: ["admin", "hr"]` と決め打ち。**画面では viewer にも編集が出ていて、押すと 403** | 定義の新規登録・編集・削除に `roles` を書いて、サーバは `canRunActionIn` で同じ1行を読む。viewer には出ない |
| 受け取る項目は `page.form` を手で歩いて拾う | `acceptRecordIn`（見えない項目・読むだけの項目も捨てる） |
| 返さない列は `page.table.columns[].roles` を手で歩く（`hideColumns`） | `visibleRecordIn`（入力欄の `roles` も見る） |
| 選択肢を列・絞り込み・入力欄に3回ずつ書いていた | 語彙（`app.vocabularies` と `optionsOf`）に1つ |

### 受注入力（Java）

| 0.9.20 まで | いま |
|---|---|
| 「入力できるのは sales と clerk」をコントローラに決め打ち。**要件では管理者は全部できるのに、画面は開けて保存で 403** | 画面の `roles: [sales, clerk, manager]`。サーバは `ServerAccess` で同じ1行を読む（API の試験 A-29 を足した） |
| 一括取消の役割は素の定義を手で歩いて引いていた（`rolesOfAction`） | `ServerAccess.canRunAction` |
| 帳票の「取消は刷らない」を SQL に手で足していた（`order_status <> ?`） | 定義の `search.fixed`。`QueryBuilder` が毎回足す（`Sql` に `notEquals` を1つ足した） |
| 明細の単価は商品を選んでも入らず、確認の金額が保存するまで分からなかった | `copy` で商品マスタの単価・税率・商品名が入る。単価は読むだけ（正はサーバ、今までどおり入れ直す） |
| 商品の並び（`orderSummary`）は商品**コード**を並べていた（名前が行に無かった） | 写した商品名を並べる |
| 修正ボタンは取消・出荷済でも押せて、押してから 409 | `enabledWhen` で入力中・確定だけ |

### 機能網羅（Node モック・3つの Renderer）

| 0.9.20 まで | いま |
|---|---|
| 入力の画面4枚に `plugin: saveItem` の「保存」（Flutter / Vue / React に同じ中身を3回） | 組み込みの保存。一覧の2画面には `type: create` を足した |
| 書き込みはいつも combo_form の入力枠で受けていた | 送ってきた項目を一番多く受け取れる画面で受ける（`acceptRecordIn`） |

## 見つけたもの

どれも**見本の側の穴**で、枠組みの不具合はありませんでした。

| | 何が起きていたか | どうやって気づいたか |
|---|---|---|
| ① | 受注入力の管理者が**保存で 403**（上の表） | 画面の `roles` を書いて、サーバの決め打ちと並べたら食い違っていた |
| ② | マスタメンテの viewer に**押すと 403 のボタン**が出ていた | 同じく |
| ③ | 機能網羅で、選択肢の連動の画面から保存すると**名前もグループも黙って捨てていた** | `saveItem` を外して組み込みの保存に寄せたとき、受ける画面を見直して |
| ④ | マスタメンテの初期データに**退職日が入社日より前**の社員が2人いた | 0.9.21 のあとの洗い出しで。画面で開いて保存すると、画面と同じ検証（退職日は入社日以降）で止まる |
| ⑤ | `tools/run-tests.sh` が、値の試験に NG があっても**「作り直しました」で終わっていた** | 下の ② |

①②は「画面の `roles` は見せ方だけ、本当の遮断はサーバ」の**両方を人が書いていた**から
起きたズレです。同じ定義を両側が読むようにしたら、ズレる場所が無くなりました。

## つまずいた所

### ① 手元の `node_modules` が古い版のままだった

`package.json` を上げたのに、手元で `hatake check` を叩くと新しいキーが全部
「知らないキー」になりました（13件）。**手元に入っていたのが 0.9.20 のまま**だった
からです（Docker の中は焼き直すので新しい）。

0.9.23 で入った `hatake doctor` がちょうどこれを見る道具で、固定した版と入っている版を
並べて出します。入れ直したあとは3本とも:

```
✓ 固定した版は 0.9.23 にそろっています（15 か所）。
✓ 入っている版は固定した版と同じです（15 か所）。
```

（`! MCP（hatake）が設定に見つかりません` は、この見本が案件ごとの MCP 設定を
持っていないだけ。使う人の手元で入れてもらう前提です。）

### ② 値の試験が落ちていたのに、通ったことになっていた

受注入力の `orderSummary` を商品名に変えたら、`hatake run` の S-01 / S-14 が
**期待と違う**になりました（シナリオの明細に商品名が無いので、並びが空になる）。
シナリオに商品名を足して直しましたが、問題はそこではなく、`run-tests.sh` が
**それでも成功で終わっていた**こと。

`|| fail=1` が囲みの最後の `echo` の終了コードしか見ていなかったので、NG が在っても
一度も落ちていませんでした。紙に `NG` が在れば落ちるように直しました。ついでに、
名前だけ「5件で切れる」と言っていて中身を見ていなかった S-15 にも、並びの期待を足しています。

### ③ JitPack は今回は一発で通った

前回は Maven Central の混雑（429）で JitPack が v0.9.20 を組めませんでしたが、
今回は v0.9.23 をそのまま組めました。

## 決めていないこと（人に返す）

| | |
|---|---|
| **受注の「入力中 → 確定」は誰が動かすか** | 修正ボタンに `enabledWhen`（状態で押せる／押せない）を書いたので、`hatake check` が `state-owner` を聞くようになった。出荷は出荷指示の口が動かすが、**確定にする手段が画面にもサーバにも無い**。業務の判断なので、答えは書いていない（`docs/2-設計/出力-残っている問い.txt` に残っている） |

## 枠組みに返すこと

| | |
|---|---|
| `state-owner` が `readOnlyWhen: { mode: edit }` だけでも出る | 新規か編集かは業務の状態ではないので、聞かれても答えようがない。マスタメンテでは `questions.decided` に理由を書いて黙らせた |
| 部署名は DB のビューのまま | 列の `optionsSource` は画面の一覧にしか効かない（CSV・紙・サーバはキーのまま）。社員マスタは CSV にも部署名が要るので、ビューで引く形を残した |

## 上げ方（やったこと）

1. `hatake.version` を `v0.9.23` に
2. `apps/*/flutter-src/pubspec.yaml` の `ref:` を3本とも差し替え
3. `apps/*/node-src/package.json` の `.tgz` の URL を差し替え（2本）
4. `apps/kitchen-sink-prj/{vue,react}-src/package.json` の `.tgz` の URL を差し替え
5. `apps/order-entry-prj/java-src/build.gradle` の JitPack の座標を差し替え
6. **手元の依存も入れ直す**（上の ①。`hatake doctor` で確かめる）
