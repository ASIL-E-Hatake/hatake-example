## 変わった紙: 「あとから変えられない」が仕分けられた

マスタメンテの依頼文の「社員番号は6桁の数字。**あとから変えられない**」の行は、今まで
どの担当にも当たらずに「当てられなかった行」に落ちていました。0.9.32 で担当表の
「条件で出し分ける」に 変更不可・変えられない などの言い方が足されたので、そこに当たる
ようになりました（書くキー: `readOnlyWhen`）。定義はもともと `readOnlyWhen: { mode: edit }` で
書いてあるので、**仕分けが定義に追いついた**形です。

→ [出力-枠組みの外の仕分け.txt](../apps/master-maintenance-prj/docs/1-要件定義/出力-枠組みの外の仕分け.txt)
（仕分けた行 14 → 15 件・当てられなかった行 28 → 27 件）

## 初見試験

同じ課題・同じモデル（claude-sonnet-5-5）・同じ Claude Code（2.1.293）で、hatake の版だけを
変えて6回ずつ回した。成績表は [v0.9.32](../evals/results/v0.9.32/成績表.md)（前の版との比較つき）。

| | v0.9.31 | v0.9.32 |
|---|---|---|
| 合格 | 6 / 6 | 6 / 6 |
| `where` の「載っていない」（のべ） | 1 | **0** |
| `reference` が空振り（のべ） | 1（`editOnly`） | 1（`readOnlyOnEdit`） |
| 空振りに意味の近いキーが添えられた（のべ） | — | **0** |
| 枠組みの中身を読みに行った試行 | 1 | 2 |
| 断られた引数（のべ）・うち近い名前つき | 2 ・ 2 | 4 ・ 4 |
| 名前だけの npx ・答えが大きすぎた試行 ・`examples` の空振り | 0 ・ 0 ・ 0 | 0 ・ 0 ・ 0 |
| 往復（平均） | 20 | 23 |

**意味の表は、今回は当たらなかった**。AI は「作ったあとは変えられない」を書こうとして、
今度は `readOnlyOnEdit` を引いた。表には `editOnly` / `readonly` / `immutable` … を載せたが、
**丸ごと一致でしか当てない**ので、`readOnly` に `OnEdit` を足しただけの名前でも外れた
（綴りの近さも2文字までなので届かない）。その試行は仕様書を grep して `readOnlyWhen` と
`$mode` を探し当てた。毎回ちがう組み合わせで来るので、**名前の中に表の言葉が含まれていれば
当てる**（`readOnlyOnEdit` ⊃ `readonly`）形にしたい。枠組みに返す。

もう1つ: **必須の引数を渡し忘れた答えに例が無い**のが、今回は 4 回（`hatake_new_page` の
`id` / `kind` / `title`）。知らない引数を断る答えには呼び方の例が付くのに、足りない答えには
付かない。0.9.30 の回から候補に置いてあったものの、回数が増えたので優先度を上げたい。
