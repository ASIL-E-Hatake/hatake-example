# 見本を 0.9.28 → 0.9.29 に上げた記録

> **中身**: 実際に上げてみて、何が起きて何が起きなかったか。
> **前の回**: [0.9.27 → 0.9.28](移行-0.9.27から0.9.28.md)。
> 枠組み側で何が変わったかは [CHANGELOG](https://github.com/ASIL-E-Hatake/hatake/blob/main/CHANGELOG.md)
> の 0.9.29。

0.9.29 は、[初見試験](../evals/)の 0.9.28 の回で見えたことを直した版です（前回の記録の
「新しく見えたこと」の3つ）。

- MCP で定義をファイルで渡す引数が **`file` → `file_path`**（Claude Code の `Read` / `Write` と
  同じ名前）。知らない引数を断るときに**近い名前**を添える
- `examples` を**言葉で**引ける（「マスタ 検索 削除確認」のように並べても当たる）
- `where` の「知らせる」は、知らせる言い方（メールで・メール送信…）にだけ当たる（項目名の
  「メール」には当たらない）

## 初見試験

同じ課題・同じモデル（claude-sonnet-5-5）・同じ Claude Code（2.1.292）で、hatake の版だけを
変えて6回ずつ回した。成績表は [v0.9.29](../evals/results/v0.9.29/成績表.md)（前の版との比較つき）。

| | v0.9.28 | v0.9.29 |
|---|---|---|
| 合格 | 6 / 6 | 6 / 6 |
| Claude Code の `Write` に `file` を渡した（のべ） | 3 | **0** |
| `examples` が空振り（のべ） | 2 | **0** |
| `file` / `file_path` で渡した（のべ） | 9 | 11 |
| `check` を MCP で ／ CLI で | 8 ／ 0 | 8 ／ 0 |
| 名前だけの npx ・答えが大きすぎた試行・`where` の「載っていない」 | 0 ・ 0 ・ 0 | 0 ・ 0 ・ 0 |
| 断られた引数（のべ） | 0 | 2 |

前回の「新しく見えたこと」の2つ（`Write` に `file`・`examples` の空振り）は消えた。

**新しく見えたこと（枠組みに返す）**:

- **断られた引数が2回**（`hatake_reference` に `key`、`hatake_new_page` に `type` / `app`）。
  断られたあと AI は正しい名前（`name` / `kind`）で呼び直せていたが、綴りが近くないので
  **近い名前は添えられなかった**。推し量られやすい言い換え（`key` / `query` → `name`、
  `type` → `kind`）の表があれば1往復早く直る
- **`hatake_reference` に `maxLength` を引くと「DSL に無い名前」**。`maxLength` はキーではなく
  検証（`validators`）の `type` に書く**値**なので索引に無い。AI が引きたいのはまさにこういう値

## 生成物

マスタメンテの「枠組みの外の仕分け」が1件減った。0.9.28 では項目の並び（「社員番号・氏名・
…・メール・内線・在籍区分。」）が「知らせる（サーバの担当）」に当たっていたが、0.9.29 では
当たらない（当てられなかった行が 27 → 28 件＝0.9.27 と同じ）。前回の記録で「直したい」と
書いた所がそのまま直った。

## 初見試験の道具

- `file` と `file_path` の両方を「ファイルで渡した」として数える
- **Claude Code の `Write` に `file` を渡して断られた回数**と、**近い名前が添えられた回数**を足した
  （0.9.28 の成績表も同じ数え方で作り直した＝`Write` に `file` は 3 回）
- 比較の表に **Claude Code の版**も並べる（違えば「差は hatake だけのせいではない」と注記）。
  成績表を書く道具は今の版の部屋を使う（前の版のイメージを消しても書き直せる）
