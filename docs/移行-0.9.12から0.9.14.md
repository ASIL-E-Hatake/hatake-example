## なぜ何も壊れなかったか

0.9.14 は `@hatake-fw/api` が出す名前を **588個 → 35個**に絞った版です。
数字だけ見ると派手ですが、**名前も形も変えておらず**、外れたものは
`@hatake-fw/api/internal` から今までどおり引けます。

この案件が枠組みから取っているのは6つでした:

| 名前 | 使っている所 |
|---|---|
| `buildQuery` | 1本目・2本目のサーバ（検索条件を組む） |
| `FormValidator` | 1本目・2本目のサーバ（画面と同じ検証） |
| `parseAppSource` | 1本目・2本目のサーバ（定義を読む） |
| `checkBulkLimit` | 2本目のサーバ（一括の上限） |
| `deriveDto` | 2本目のサーバ（受け口の宣言） |
| `toOpenApi` | 2本目のサーバ（OpenAPI を出す） |

**6つとも約束する面に残っていました。** 上げる前に確かめたい場合は、
`import` している名前を集めて 35個の一覧と突き合わせれば1分で分かります:

```bash
grep -rn "@hatake-fw/api" --include=*.js --include=*.mjs --include=*.ts . | grep -v node_modules
```

## 上げ方（やったこと）

1. `hatake.version` を `v0.9.14` に
2. `apps/*/flutter-src/pubspec.yaml` の `ref:` を3本とも差し替え
3. `apps/*/node-src/package.json` の `.tgz` の URL を2本とも差し替え
4. `apps/order-entry-prj/java-src/build.gradle` の JitPack の座標を差し替え
5. 回す

**版の数字を、固定している所と履歴の記述とで分けること。** `README.md` の
「0.9.12 で直り…」や `CLAUDE.md` の「0.9.12 から `detail-page-in-menu` が言う」は
**起きたことの記録**なので、上げてはいけません。まとめて `sed` を当てると、
過去の話が嘘になります。

## つまずいた所（枠組みとは関係ない2つ）

上げること自体は何も起きませんでしたが、**確かめる段で2つ止まりました**。
どちらも Windows の改行コードが原因です。

### ① シェルスクリプトが1行目から落ちる

```
tools/run-tests.sh: line 9: set: pipefail: invalid option name
```

`core.autocrlf=true` の checkout で `set -euo pipefail` が `pipefail\r` になり、
コンテナの bash が知らない旗として弾きます。**画面に出る字からは改行が原因だと
分かりません。**

### ② エビデンスの差分が、回した人によって変わる

`definitions/app.yaml` が CRLF のままイメージに焼かれると、API が返す字数が
変わります。API テストの記録は長い本文を 1200 文字で切るので、**切れる位置が
ずれて差分が出る**。誰がどの環境で回したかで記録が変わると、証拠になりません。

→ どちらも `.gitattributes` に `* text=auto eol=lf` を置いて直しました。
ここのものは全部 Linux のコンテナで動くので、手元でも LF で置くのが正解です。

### おまけ: `npx` の shim が黙る

Windows のバインドマウント越しに `node_modules/.bin/hatake` を叩くと、
**何も出さずに終了コード 0 で終わります**。テストの集計は出力を数えているので
「通った件数: 0」とだけ出て、失敗にもなりません。`node …/dist/cli.js` を直に
叩けば動きます。手元で回すときは `HATAKE` を上書きしてください:

```bash
HATAKE="node /path/to/node_modules/@hatake-fw/api/dist/cli.js" bash tools/run-tests.sh
```
