## ① 0.9.24 の検証が、機能網羅の書き間違いを見つけた

「見せる相手で変わる」のコードの欄に、こう書いていた:

```yaml
readOnlyWhen: { field: $mode, equals: edit }
```

条件に書ける鍵は `field` / `operator` / `value` / `mode` と結合だけで、`equals` は**黙って
捨てられる**。残るのは**値の無い equals**＝その項目が空のときだけ成り立つ条件で、`$mode` と
いう項目はレコードに無い（いつも空）ので、**いつも成り立つ**。新規のときもコードが
入れられなかった。0.9.23 までの `check` は警告 0 だった。

0.9.24 の `validate` はこう言う:

```
警告 …readOnlyWhen.equals: 条件に `equals` という鍵は書けません。黙って捨てられ、**値の無い equals**＝…
警告 …readOnlyWhen.field: 新規か編集かは項目ではありません（`$mode` という項目はレコードに無い）。…
     → `{ mode: edit }` / `{ mode: create }` と書いてください。
```

`{ mode: edit }` に直した。

## ② ブラウザ版の出力先を、出来合いに乗り換えた

機能網羅の Vue / React は、CSV と印刷の口を自前で書いていた（`sinks.ts`。刷っても PDF は
できず、`window` に紙を置くだけ）。0.9.25 の `downloadCsv` / `downloadPdf` を登録するだけにして、
`sinks.ts` を消した。案件が書くファイルは 4 つから 3 つになった。

画面の試験（`shots-web.mjs`）は、帳票で**印刷を押して、`%PDF-` で始まるファイルが保存された
か**まで見るようにした（できなければ撮らずに落とす）。Vue / React とも通った。

機能網羅の CSV は文字コードを指定していない（UTF-8）ので、`downloadCsv` が断る形
（cp932 など）には当たらない。

## ③ 一緒にやったこと: 変更耐性の記録

受注入力で、作ったあとに業務の変更を3つ（項目を足す・規則を変える・権限を変える）、
hatake 版と無し版の両方に入れて測った。→ [変更に強いか](../apps/order-entry-prj/docs/まとめ/変更に強いか.md)

そのとき見本の側の穴が2つ見つかった（どちらも直した）:

- hatake 版のサーバの `Sql.java` に前方一致（`startsWith`）が無く、**黙って完全一致**に
  していた（定義に書けば `QueryBuilder` はそのまま渡してくる）
- 無し版は、入れる人を `sales` / `clerk` に決め打ちしたままで、0.9.23 で足した試験（A-29
  「管理者も受注を入力できる」）に落ちていた

## 上げ方（やったこと）

1. `hatake.version` を `v0.9.25` に
2. `apps/*/flutter-src/pubspec.yaml` の `ref:` を3本とも差し替え
3. `apps/*/node-src/package.json`（2本）と `apps/kitchen-sink-prj/{vue,react}-src/package.json` の `.tgz` の URL を差し替え
4. `apps/order-entry-prj/java-src/build.gradle` の JitPack の座標を差し替え（今回も一発で組めた）
5. 手元の依存を入れ直して、`hatake doctor` で版のずれが無いことを確かめる
