# 見本を 0.9.25 → 0.9.26 に上げた記録

> **中身**: 実際に上げてみて、何が起きて何が起きなかったか。
> **前の回**: [0.9.23 → 0.9.25](移行-0.9.23から0.9.25.md)。
> 枠組み側で何が変わったかは [CHANGELOG](https://github.com/ASIL-E-Hatake/hatake/blob/main/CHANGELOG.md)
> の 0.9.26。

0.9.26 は1件だけの直しです: **`npx hatake …` が何も出さずに終了コード 0 で終わっていた**
（bin の入口の判定が、npm の張るリンクに当たっていなかった）。見つけたのはこの見本の
[30分サンプル](../apps/starter-prj/)で、道具をコンテナに `npm i -g` して叩いたら何も出なかった。

## 結論から

| | 上げるために直した所 |
|---|---|
| 定義・Flutter・Vue / React・Node・Java | **0 か所** |
| 参照の差し替え | 10 ファイル（`v0.9.25` → `v0.9.26`）＋ 30分サンプル |
| 道具（`tools/`） | **既定の `hatake` の取り方を変えた**（下の ①） |

## ① 道具の既定を「名前だけの `npx hatake`」から「Release を名指し」に変えた

`tools/refresh-docs.sh` / `run-tests.sh` / `build-design-docs.mjs` は、`HATAKE` を渡さなければ
`npx --yes hatake` を叩く作りでした。0.9.25 までは bin の不具合で**何も出ずに 0**、0.9.26 で
それが直ると今度は別の問題が見えました:

**npm の registry に `hatake` という名前の別の道具がある**（ほかの人が作った、シンボリックリンクを
張る道具。名前が同じだけ）。枠組みの `@hatake-fw/api` は registry に出していないので、手元に
入っていない場所で `npx --yes hatake` と打つと、**その別の道具を取ってきて、こちらの引数で
走らせる**。この見本の道具は案件の根（`node_modules` が無い所）で叩くので、まさにその形でした。

これまで実際に走ったことはありません（見本を回すときは毎回 `HATAKE=node …/dist/cli.js` を
渡していた）。既定を、`hatake.version` の Release を名指しして取る形に変えました:

```bash
npx --yes --package=https://github.com/ASIL-E-Hatake/hatake/releases/download/v0.9.26/hatake-fw-api-0.9.26.tgz hatake
```

`HATAKE` を渡さずに3本の `refresh-docs.sh --check` / `build-design-docs.mjs --check` /
`run-tests.sh` を回して、今までと同じ紙が出ることを確かめています。

> 枠組みの手引きにも `npx hatake …` と書いてある所が多く、同じことが起きうる。
> 枠組みの側に返す（registry に出すか、書き方を変えるか）。

## ② 30分サンプルの道具は `npm i -g` で入れている

[30分サンプル](../apps/starter-prj/)の `docker compose run --rm hatake …` は、コンテナの中に
Release の tarball を `npm i -g` している（名前で取りに行かない）。0.9.26 で、そのまま
`hatake check` / `hatake explain` が答えるようになりました。Claude Code から道具（MCP）を
Docker で繋ぐ [`.mcp.json`](../apps/starter-prj/.mcp.json) も、名乗る版 0.9.26・道具 23 本で
繋がることを確かめています。

- 機能網羅: シナリオ 7 ／ API 12 / 12 ／ 画面 Flutter 10・Vue 12・React 12 ／ 突き合わせ 10 / 10

- `analyze` clean ×3 ／ `hatake doctor` 版のずれ 0 ×3 ／ リンク切れ 0

### 受注入力の Java は JitPack が一度落ちた

JitPack が v0.9.26 を組むのに一度失敗しました（`gradle-wrapper.jar` を開けない。v0.9.25 と
中身は同じファイル＝こちらの変更ではない）。[0.9.20 のとき](移行-0.9.14から0.9.20.md)と同じで、
JitPack は失敗を覚えているので、**失敗した版を消して頼み直し**ました。組み直したあと、
JitPack の v0.9.26 から焼き直して上の試験を回しています。

落ちたまま試験を回すと、API は叩けず画面も0枚で、**記録の紙が失敗の結果で上書きされる**
（`run-tests.sh` は都合の悪い結果も残すので）。組み直すまで、記録は前の版のものに戻して
おきました。
